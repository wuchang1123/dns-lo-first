# Local First - 本地优先 DNS 服务器方案

基于 Go 开发的本地 DNS 服务器，目标是在不明显牺牲解析速度的前提下，优先返回可信结果，并通过缓存、分流和校对降低 DNS 污染影响。

- IPv4 Only：本服务只处理 A 记录；AAAA 查询直接转发，不做污染识别和缓存增强。
- 终端按 Ctrl+C 退出，优雅停止 DNS 服务器。
- MVP 同时实现 Do53、DoH 和完整上游评分。
- 目标部署环境为 OpenWrt x86_64，MVP 需要能在 OpenWrt 上以常驻服务运行。

## 设计原则

- 查询路径必须可解释：每次响应都能从日志看出命中了哪条规则、用了哪个上游、是否来自缓存。
- 默认策略以海外结果为主，本地结果用于加速和校对，不让不可信本地结果覆盖海外结果。
- 缓存优先保证稳定性，过期缓存可以短 TTL 返回并后台刷新。
- ASN 检查作为强规则，不假设 `domain_asn.yaml` 覆盖所有域名。
- 先实现稳定 MVP，再根据运行日志微调评分权重和分流策略。

## 文件

- 配置文件：`config.yaml`
- GFW 域名列表：`data/common_blocked_domains.txt`，支持注释和空行。
- ASN 信息：`data/domain_asn.yaml`，维护域名、组织和 IP 段映射。
- 本地域名列表：`local_domains.file_path` 指向的文件，由 `local_domains.source_url` 定时更新。
- OpenWrt 推荐目录：
    - 程序：`/usr/bin/dns-lo-first`
    - 配置：`/etc/dns-lo-first/config.yaml`
    - 数据：`/etc/dns-lo-first/data`
    - 缓存：`/var/cache/dns-lo-first`
    - 日志：`/var/log/dns-lo-first`

## 配置

### Server

- `server.listen`：监听地址。
- `server.domain_ttl`：正常响应写入缓存时使用的默认 TTL。
- `server.concurrent_timeout`：本地和海外并发查询的总等待窗口，默认 6 秒。
- `server.log_timezone`：日志时区。
- `server.log_level`：日志等级。
- `server.log_path`：日志目录。
- `server.cache_path`：缓存目录。
- `server.cache_size`：内存缓存最大条目数。
- OpenWrt 环境下建议使用绝对路径，避免服务启动目录变化导致配置、缓存或日志写到错误位置。

### Bootstrap DNS

- `bootstrap_dns` 用于下载配置、更新域名列表时解析数据源域名。
- 只支持 Do53，格式为 `host:port`。
- Bootstrap DNS 不使用 DoH，避免启动早期 HTTPS、证书校验和域名解析形成循环依赖。
- 留空时优先使用配置中的非回环上游 DNS；若仍为空，则内置 `223.5.5.5:53`、`8.8.8.8:53`、`1.1.1.1:53`。

### Upstream

- 上游分为 `local` 和 `overseas` 两类。
- MVP 阶段支持普通 DNS over UDP/TCP 和 DNS over HTTPS。
- Do53 上游格式为 `host:port`。
- DoH 上游格式为 HTTPS URL，例如 `https://dns.google/dns-query`、`https://cloudflare-dns.com/dns-query`。
- DoH 使用 RFC 8484 wireformat，请求方法优先使用 POST，`Content-Type` 为 `application/dns-message`。
- DoH 上游域名解析使用 `bootstrap_dns`，解析结果可短期缓存，避免查询链路依赖本机 DNS。
- Do53 和 DoH 合并进入同一套上游健康度统计，按具体上游地址记录延迟、成功和失败。
- 单个上游请求超时时间默认 3 秒，可通过配置扩展。
- EDNS Client Subnet 由配置固定控制：关闭时移除客户端请求里的 ECS，开启时先移除原 ECS，再注入配置中的固定 ECS。

## 智能分流

分流规则优先级固定为：

1. `upstream.overseas_only`
2. `upstream.local_only`
3. `local_domains`
4. 默认并发策略

匹配规则：

- 普通域名匹配 apex 和所有子域，例如 `example.com` 匹配 `example.com` 和 `a.example.com`。
- 通配符 `*.example.com` 只匹配严格子域，符合 RFC 4592，不匹配 `example.com` 本身。
- `local_domains` 支持定时更新，更新后热加载。

## 缓存

### 基础响应缓存

基础响应缓存负责 DNS 响应的快速返回。

- 缓存 key：`qname + qtype + qclass`。
- 内存缓存 value 至少包含：DNS 响应、创建时间、过期时间、来源上游、来源类型、本次是否通过 ASN 检查。
- 文件缓存不保存 packed DNS message，只保存 question、answer、authority、additional、rcode、时间和上游信息，保证人可读并节省空间。
- 未过期：立即返回缓存结果，本次查询结束。
- 已过期：立即返回旧结果，响应 TTL 固定为 3 秒，然后触发后台刷新。
- 后台刷新需要按 key 去重，同一个 key 同一时间只允许一个刷新任务运行。
- 清理策略：每天定时删除创建时间早于 48 小时的条目。
- 存储方式：内存 + 文件持久化。内存用于快速响应，文件使用人可读格式。

### 校对结论缓存

校对结论缓存只保存本地和海外结果的比较结论，不直接替代基础响应缓存。

- 缓存 key：建议按 `qname` 维度保存，也可包含 `qtype`。
- 缓存 value 至少包含：本地响应 IP、海外响应 IP、对应上游、一致性结论、更新时间、过期时间。
- 过期时间可配置。
- 只用于优化默认并发策略，不用于 `local_only`、`local_domains`、`overseas_only` 的强制规则。
- 与基础响应缓存独立存储，互不覆盖。

## 上游选择和评分

MVP 阶段实现完整上游评分：

- 每类上游维护独立候选池，`local` 和 `overseas` 互不竞争。
- Do53 和 DoH 可以混合配置在同一类上游中，选择逻辑不按协议特殊优先。
- Do53 和 DoH 合并统计，只按具体上游地址区分，不按协议额外拆分。
- 每个上游记录最近延迟、成功次数、失败次数、连续失败次数、冻结截止时间、最近使用时间。
- 分数由延迟、成功率和失败惩罚共同决定。
- 分数高的上游优先使用。
- 分数相等时随机选择，避免配置靠前的上游长期占用全部流量。
- 首选上游超时时，立即并发尝试同类剩余可用上游。
- 单个上游超时后冻结 1 分钟，冻结期间不参与正常选择。
- 同类型全部冻结时，解冻最早被冻结的上游，避免该类完全不可用。
- 所有上游都超时时，该类查询失败。
- 每小时给低分但未冻结的上游一次探测机会，避免低分上游永久饥饿。
- 评分状态保存在内存即可，重启后从初始分数重新开始。

## ASN 污染检查

ASN 检查用于 `domain_asn.yaml` 中有定义的重点域名。

- 配置文件需要提供开关。
- 命中域名规则时，检查返回 IP 是否落入该域名对应的组织的 IP 段。
- 通过检查：响应可信，可返回并写入基础响应缓存。
- 未通过检查：视为疑似污染，不写入基础响应缓存。
- 「ASN 未通过后并发换上游」仅适用于**海外类**上游；本地类不因 ASN 失败对本组做全员并发重试。
- 如果同类所有上游都未通过 ASN 检查，可返回最后一个结果，但必须：
    - 打印 Warn 日志。
    - 响应 TTL 固定为 30 秒。
    - 禁止更新基础响应缓存。

注意：ASN 检查是强规则，不命中 `domain_asn.yaml` 不代表结果可信或不可信。

## 校对比较

默认并发策略下，本地和海外都有结果时进行校对比较。

一致条件建议分级：

- 强一致：两边 IP 集合有交集。
- 组织一致：命中 `domain_asn.yaml`，且两边 IP 都属于允许组织或 IP 段。
- 弱一致：两边 IP 至少有一个位于相同 `/24` 网段；如果 `/24` 不匹配，再检查相同 `/16` 网段。

`/16` 可作为更宽松的弱一致条件，用于减少海外和本地 CDN 调度差异带来的误判。

校对结果用途：

- 更新校对结论缓存。
- 帮助后续默认并发查询决定是否可以接受更快返回的一侧。
- 不覆盖 `overseas_only`、`local_only` 和 `local_domains` 的强制分流规则。

## 查询流程

### 0. 请求预处理

1. 标准化 `qname`，统一大小写和结尾点处理。
2. 只对 A 记录执行增强逻辑。
3. AAAA 和其他未支持类型直接转发到合适上游，不进入 ASN 检查。
4. 生成缓存 key：`qname + qtype + qclass`。

### 1. 基础缓存命中

1. 如果基础缓存存在且未过期，立即返回缓存结果，本次查询结束。
2. 如果基础缓存存在但已过期：
    - 立即返回旧结果，响应 TTL 固定为 3 秒。
    - 如果当前 key 没有后台刷新任务，启动后台刷新。
    - 客户端本次查询结束，后台逻辑不再向客户端写响应。

### 2. `local_only` 和 `local_domains`

只查询本地类上游。

1. 从本地类首选上游开始查询。
2. 首选上游超时时，并发尝试剩余本地上游。
3. 任一上游返回成功响应后立即返回客户端，并更新基础响应缓存。
4. 总等待超过 `server.concurrent_timeout`：
    - 如果已有本地响应，返回该响应，TTL 固定为 3 秒。
    - 如果没有任何响应，返回上游失败或空响应，按 DNS 错误处理。

### 3. `overseas_only`

只查询海外类上游。

1. 如果域名命中 `domain_asn.yaml`：
    - 查询海外首选上游。
    - 响应通过 ASN 检查时，立即返回并更新基础响应缓存。
    - 响应未通过 ASN 检查时，并发尝试剩余海外上游。
    - 如果有任一剩余上游通过 ASN 检查，立即返回并更新基础响应缓存。
    - 如果所有海外上游均未通过 ASN 检查，返回最后一个响应，TTL 固定为 30 秒，打印 Warn 日志，不更新基础响应缓存。
2. 如果域名未命中 `domain_asn.yaml`：
    - 任一海外上游成功响应后立即返回，并更新基础响应缓存。
3. 总等待超过 `server.concurrent_timeout`：
    - 如果已有海外响应，返回该响应，TTL 固定为 3 秒。
    - 如果没有任何响应，返回上游失败或空响应，按 DNS 错误处理。

### 4. 默认并发策略

默认域名同时查询本地类和海外类上游。

核心原则：

- 海外响应优先用于返回和基础缓存。
- 本地响应用于校对、日志和后续优化。
- 未命中 ASN 规则时，不让本地响应抢先覆盖海外结果。
- 命中 ASN 规则时：**只有海外类上游**在单次响应未通过 ASN 检查时，才并发尝试同类剩余上游。**本地类上游**不因 ASN 校验失败而并发扫剩余本地上游（本地仍可按首选超时等通用策略并发，与 ASN 无关）。

流程：

1. 并发启动本地类查询和海外类查询。
2. 如果域名命中 `domain_asn.yaml`：
    - 本地类：按上游选择与超时策略查询（如 `QueryFirst`），不因 ASN 失败对本组发起「全员并发重试」。
    - 任一海外响应通过 ASN 检查时，立即返回客户端并更新基础响应缓存。
    - 海外响应未通过 ASN 检查时，**仅并发尝试剩余海外上游**。
    - 本地响应通过 ASN 检查时可以记录为校对数据，但不优先于海外响应写入基础缓存。
    - 如果所有海外上游均未通过 ASN 检查，但本地响应通过 ASN 检查，可返回本地响应，TTL 固定为 30 秒，打印 Warn 日志，不更新基础响应缓存。
    - 如果所有可用响应都未通过 ASN 检查，返回最后一个海外响应，TTL 固定为 30 秒，打印 Warn 日志，不更新基础响应缓存。
3. 如果域名未命中 `domain_asn.yaml`：
    - 默认等待海外响应。
    - 海外响应成功后立即返回，并更新基础响应缓存。
    - 本地响应如果先到，只记录并等待海外响应。
    - 如果存在未过期且一致的校对结论缓存，可允许本地或海外任一成功响应先返回，但基础响应缓存仍优先使用海外响应更新。
4. 本地和海外都有结果后，在后台执行校对比较并更新校对结论缓存。
5. 总等待超过 `server.concurrent_timeout`：
    - 有海外响应：返回海外响应，并更新基础响应缓存。
    - 无海外响应但有本地响应：返回本地响应，TTL 固定为 3 秒，不更新基础响应缓存，后台继续等待海外结果用于校对。
    - 两边都无响应：返回上游失败或空响应，按 DNS 错误处理。

## 后台刷新

后台刷新用于过期缓存和默认并发策略的后续校对。

- 后台任务必须按缓存 key 去重。
- 后台任务不能再次向客户端写响应。
- 后台刷新成功后，根据正常查询规则更新基础响应缓存和校对结论缓存。
- 后台刷新失败只记录日志，不删除旧缓存。

## 日志系统

### 基础日志

- 日志等级：debug、info、warn、error、fatal。
- 日志时区：Asia/Shanghai。
- 日志时间精确到毫秒。
- 日志年份只显示最后两位。
- 每天 0 点清除超过 48 小时的日志，启动时不清理。
- Warn 日志必须覆盖：
    - ASN 检查失败但仍返回。
    - 默认策略无海外响应而返回本地响应。
    - 所有上游超时。
    - 缓存文件读取或写入失败。

### 性能日志

独立写入 `query.log`。

- 每个查询记录从进入到返回客户端的总耗时。
- 耗时统一使用毫秒，保留 3 位小数，四舍五入。
- 日志格式前面统一显示时间和耗时。
- 至少包含：`qname`、`qtype`、`qclass`、命中规则、缓存状态、返回上游、响应 IP、rcode。
- 无错误时不输出 rcode。
- 记录每次上游查询的分段耗时，包含上游信息、开始时间、结束时间。
- DoH 查询需要记录 TLS 证书校验分段耗时，包含域名、IP、开始时间、结束时间。

## 定时更新

- 按 `local_domains.update_interval` 定时下载本地域名列表。
- 启动时如果 `local_domains.file_path` 不存在，需要立即下载更新一次。
- 下载使用 `bootstrap_dns` 做域名解析。
- 下载成功后校验文件格式，再原子替换本地文件。
- 替换成功后热加载规则。
- 下载失败保留旧文件和旧规则，只记录 Warn 或 Error 日志。

## OpenWrt 部署

OpenWrt x86_64 是首要部署目标。

- 构建目标：`GOOS=linux GOARCH=amd64`。
- 优先提供静态二进制，减少 OpenWrt 运行时依赖。
- 默认不依赖 systemd，提供 `/etc/init.d/dns-lo-first` procd 服务脚本。
- 服务脚本需要支持 `start`、`stop`、`restart`、`reload`。
- `reload` 用于重新加载配置和域名规则，不能中断已有查询。
- 默认监听端口建议先使用 `:5355`，避免和 OpenWrt 自带 `dnsmasq` 的 53 端口冲突。
- 如果要接管 53 端口，需要在部署文档中说明如何调整 `dnsmasq`、防火墙和 LAN DHCP 下发的 DNS。
- 日志和缓存目录需要在服务启动前创建，并保证运行用户有读写权限。
- `/tmp` 在 OpenWrt 上通常是内存文件系统，不能作为长期缓存目录。
- CA 证书依赖需要明确：DoH 需要系统存在可信 CA 证书，缺失时应在日志中给出明确错误。
- 配置文件和数据文件应放在可持久化分区，避免系统重启后丢失。

## 构建支持

- 提供 Makefile 构建脚本。
- MVP 必须支持 OpenWrt x86_64。
- 开发阶段可保留 macOS/Linux 本机运行目标，方便调试。
- 后续再扩展 arm64 和其他平台。

## MVP 实现顺序

1. 配置加载、日志、基础 DNS 监听。
2. 上游 Do53 查询、本地/海外分类、超时和冻结。
3. 上游 DoH 查询、DoH 域名 bootstrap 解析、TLS 耗时日志。
4. 完整上游评分：延迟、成功率、失败惩罚、冻结、随机同分和低分探测。
5. 分流规则：`overseas_only`、`local_only`、`local_domains`、默认策略。
6. 基础响应缓存：内存 + 文件、过期短 TTL 返回、后台刷新去重。
7. ASN 检查：读取 `domain_asn.yaml`，命中域名执行强校验。
8. 默认并发策略：海外优先、本地校对、超时降级。
9. 校对结论缓存和性能日志。
10. 定时更新本地域名列表。
11. OpenWrt x86_64 构建、目录布局和 procd 服务脚本。
